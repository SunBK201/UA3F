# TCP 混淆注入

开启 TCP 混淆注入后，UA3F 会在收到服务器返回的 `SYN+ACK` 包时，经 TTL 检查后向服务器发送一个携带 64 字节随机 payload 的低 TTL 包。注入发生在握手过程中，不等待三次握手完成。

该混淆包用于干扰 DPI 设备的内容重组状态机。为了避免混淆包影响真实 TCP 通信，它的 TTL 会设置得较低，默认值为 `3`，使其预期在传输途中被丢弃，而不会到达目标服务器。

```yaml
desync:
  inject: true
  inject-ttl: 3
```

UA3F 以收到的服务器 `SYN+ACK` 包为参照，交换源/目标 IP 地址和端口，构造客户端 → 服务器方向的原始 TCP 包。该包设置 `ACK`、`PSH` 标志，窗口为 `65535`，序列号取自 `SYN+ACK` 包的确认号，确认号为其序列号加 `1`。

payload 为启动注入功能时生成的 64 字节随机数据，后续注入包复用这份数据。

该包预期在传输途中过期。UA3F 会根据观测到的 TTL/Hop Limit 估算距离，避免配置的 `inject-ttl` 高于估算距离。

如果同时开启固定 TTL 重写，出站流量中可能同时存在正常 TTL 包和低 TTL 注入包。例如常规出站包 TTL 为 `64`，注入包 TTL 为 `3`。
